StApiの構成や使用方法について説明します。

StApiの構成

StApiは、USB3Vision, GigEVision, CoaXPressカメラ用のAPIです。APIの機能は大きく3つに分類されます。

  1. カメラ制御機能(Transport Layer)
    カメラの設定変更や画像データ、イベントデータ等を取得する機能が提供されます。カメラとの通信にはGenTLモジュールが使用されます。SDK付属のGenTLモジュールはUSB3VisionおよびGigEVisionに対応しています。CoaXPress用取り込みボードメーカー製のGenTLモジュールを使用することでCoaXPressカメラも利用できます。カメラの設定変更にはGenApiが使用されます。画像処理機能やGUI機能が不要であれば、この機能(下図の水色線枠内)だけを使用してアプリケーションを開発できます。
    モジュール主な用途
    SystemCTIファイル(GenTL用DLLファイル)の情報取得に使用されます。
    Interfaceインターフェースに関する設定や接続されているカメラの情報取得などに使用されます。
    Deviceカメラの設定に使用されます。
    Data Stream画像データ等のストリーミングの設定に使用されます。
    Stream Bufferストリーミングに使用されているバッファの情報取得に使用されます。
  2. 画像処理機能(Image Processing)
    フォーマット変換(ベイヤー画像の色補間処理)やFFCなどの画像処理や、静止画ファイル, 動画ファイルの生成機能が提供されます。提供される機能は大きく下記の3つに分類されます。
    タイプ特徴
    Filter 入力された画像データが処理後のデータで上書きされます。ピクセルフォーマットは変化しません。
    モジュール用途
    Field Flat Correction Filter照明ムラ等に対する補正に使用されます。
    Noise Reduction Filterノイズ軽減処理に使用されます。
    Gamma Correction Filterガンマ補正に使用されます。
    Edge Enhancement Filterエッジ強調に使用されます。
    Color Transformation FilterRGBデータに対する行列演算に使用されます。
    Chroma Suppression Filter高輝度部/低輝度部の着色を抑制に使用されます。
    Balance Ratio Filterホワイトバランス処理に使用されます。カメラ側にホワイトバランス処理が実装されている場合は、不要な機能です。
    Graph Data Filterグラフ表示用データの生成に使用されます。
    Image Averaging Filter平均化された画像データの生成に使用されます。
    Converter 指定したバッファへ画像データが出力されます。ピクセルフォーマットが変化することがあります。
    モジュール用途
    Pixel Format Converterピクセルフォーマット変換に使用されます。
    Reverse Converter画像の上下左右反転処理や回転処理に使用されます。カメラ側に上下左右反転が実装されている場合は、PCの負荷を軽減するため、カメラ側の処理を使用してください。
    Filer 静止画ファイルや動画ファイルを生成します。
    モジュール主な用途
    Still Image Filer静止画ファイルの保存に使用されます。
    Video Filer動画ファイルの保存に使用されます。
  3. GUI機能
    GUIが提供されます。
    モジュール主な用途
    Device Selectionカメラ選択ウィンドウの表示に使用されます。
    Image Displayプレビューウィンドウの表示に使用されます。
    Node Map Displayノードマップ表示(設定)ウィンドウの表示に使用されます。
    Graph Displayグラフ表示ウィンドウの表示に使用されます。

対応環境

StApiCは下記の環境に対応しています。

  • Linux OS (C++と同様)

StApiCは下記の開発環境で動作確認を行っております。

  • Linux OS: gcc

(※) 使用される環境によっては、下記のような対応が必要となります。

libファイルの作成 SDKに付属しているlibファイルが使用できない場合は、libファイルを生成し、リンクを行う必要があります。C++Builderを使用して64bit版のライブラリを使用する場合は、本SDKに添付されているFree C++ Compiler用の32bit版のlibファイルは使用できませんので、コマンドプロンプトから下記のようなコマンドを実行して、DLLファイルからlibファイルを生成する必要があります。
mkexp StApi_C_MD_BCC_v1_1.a StApi_C_MD_VC141_V1_1.dll
生成されたlibファイルは%STAPI_ROOT_PATH%lib/x64/へコピーし、生成したlibファイルの名称に応じてStApi_C.hでリンクされているlibファイルの名称を書き換えてください。
ディレクトリの設定 インクルードファイルやライブラリのパスを指定する必要があります。 Visual C++ 6.0では、[プロジェクト][オプション]の[ディレクトリ/条件]に下記のパスを追加します。
  • インクルードパス
    $(STAPI_ROOT_PATH)Include/StApi/; $(STAPI_ROOT_PATH)Include/GenICam/
  • ライブラリパス
    32ビット版:$(STAPI_ROOT_PATH)lib/Win32/
    64ビット版:$(STAPI_ROOT_PATH)lib/x64/
使用するランタイムライブラリの指定

Visual C++ 6.0では、[プロジェクト][設定]の[C/C++][コード生成]の「使用するランタイムライブラリ」で、「マルチスレッド」もしくは「マルチスレッド(Dll)」およびそれらのDebugバージョンを指定します。「シングルスレッド」および「シングルスレッド(デバッグ)」が指定されている場合はビルドできません。

サンプルプログラムのビルド方法

各開発環境ごとのビルド方法は下記のとおりです。 サンプルプログラムをビルドする前に、予め圧縮されているC言語用のサンプルプログラム(Sample_C.zip)を書き込み権限のあるパスに展開してください。 開発環境によってはサンプルプログラムのprintf関数などの書式型指定子のサイズ プレフィックスの変更が必要な場合があります。

Visual C++

StApiCはStApi(C++)を直接使用できない開発環境のために用意されているAPIです。Visual C++ 2005以降の環境を御使用の場合は、StApi(C++)を直接使用されることを推奨いたします。 Visual C++ 6.0でサンプルプログラムをビルドする場合、ワークスペースファイル「Sample_C++6_2003.dsw」を使用します。

MinGW(gcc)

MinGW(gcc)を使用する場合、下記の手順でサンプルプログラムをビルドします。

  1. mingw-get-setup.exeを実行してMinGWのインストールを行い、mingw32-base,mingw32-gcc-g++を選択して追加します。
  2. binフォルダをPATHへ登録します。
  3. コマンドプロンプトを開きます。
  4. サンプルプログラムのフォルダへ移動して、下記のコマンドを実行します。
    > mingw32-make
  5. BuildAllForMinGW.batを実行するとすべてのサンプルプログラムがビルドされます。

Embarcadero(Borland)社 C++ Compiler / Builder

Embarcadero(Borland)社 C++ Compiler / Builderを使用する場合、下記の手順でサンプルプログラムをビルドします。

  1. C++ Compiler / Builderをインストールし、コンパイラのパスがPATHへ登録された状態にします。バージョンによってはbcc32.exeと同じフォルダへ下記のような内容のbcc32.cfgファイルを作成し、標準インクルード/ライブラリファイルの場所を指定する必要があります。詳細につきましては、C++ Compiler / Builderのドキュメントをご参照ください。
    -I"C:\borland\bcc55\include"
    -L"C:\borland\bcc55\lib"
  2. コマンドプロンプトを開きます。
  3. サンプルプログラムのフォルダへ移動して、下記のコマンドを実行します。
    > make -fBCCmakefile
  4. BuildAllForBCC.batを実行するとすべてのサンプルプログラムがビルドされます。

文字列を取得する関数について

文字列を取得する関数の引数には、文字列用バッファ(char *szText)およびそのサイズ(size_t *pnLen)が必要になります。取得する文字列のサイズが不明な場合は、下記に示すコードのように、文字列バッファにNULLを指定して関数を呼び出すことで文字列のサイズが取得できますので、必要なバッファを確保した後、改めて関数を呼び出してください。

PGenApi_INode_Functions_t pINode = psApiFunctions->GenApi->INode;
size_t nLen;
pINode->GetNameA(pINodeHandle, false, NULL, &nLen);
char *szText = (char*)malloc(nLen);
pINode->GetNameA(pINodeHandle, false, szText, &nLen);
...
free(szText);

Linux インストーラーとアンインストーラー

インストールする際は、SentechSDK-xxx-xxx.tgzを解凍し、インストーラー（.runファイル）を実行してください（スーパーユーザーのパスワードが必要）。

$ tar xf SentechSDK-xxx-xxx.tgz
$ cd SentechSDK-xxx-xxx
$ ./SentechSDK-xxx-xxx.run

インストールパスの既定値は/opt/sentechになります。インストールパスはSTAPI_ROOT_PATH環境変数に保存されます。 全ての質問に対して自動でYesと返答し、インストール先を/opt/sentechに設定する場合は、以下のようなコマンドを実行します。

$ ./SentechSDK-xxx-xxx.run --accept -- "-y -p /opt/sentech"

インストール結果は下記のとおりです。

ファイルやディレクトリー内容
/etc/udev/rules.d/30-stcam.rulesUSB3Visionカメラのアクセスするためのudevルール
${STAPI_ROOT_PATH}/.stprofile SDK用の環境変数の設定.
変数内容
STAPI_ROOT_PATH=インストールパス既定値は/opt/sentechとなります。
GENICAM_GENTL64_PATH=${STAPI_ROOT_PATH}/lib:${GENICAM_GENTL64_PATH}GenTLモジュールへのパス(32bit環境時は64ではなく32になります)
LD_LIBRARY_PATH=${STAPI_ROOT_PATH}/lib:${STAPI_ROOT_PATH}/lib/GenICam:${LD_LIBRARY_PATH}Sentech SDK用のライブラリパス
LIBRARY_PATH=${STAPI_ROOT_PATH}/lib:${STAPI_ROOT_PATH}/lib/GenICam:${LIBRARY_PATH}

Path for using sentech SDK

自動的に設定したい場合は、「source ${STAPI_ROOT_PATH}/.stprofile」をログインスクリプトに追加してください:
$ echo 'source ${STAPI_ROOT_PATH}/.stprofile' >> $HOME/.bashrc
或いは、グローバルで全てのユーザーに適用したい場合はスーパーユーザーで/etc/profile.d/stprofile.sh へ/opt/sentech/.stprofileをコピーください：
$ sudo cp ${STAPI_ROOT_PATH}/.stprofile /etc/profile.d/stprofile.sh
${STAPI_ROOT_PATH}/bin/*
  • ./GigECameraIPConfig: GigEカメラのIP設定
  • ./StFWUpdater: GigEカメラのファームウェア更新ツール

  • ./setusb.sh: USBサブシステムに割り当てられるメモリの制限を解除するスクリプト
  • ./setnetwork.sh: ネットワークデバイスの設定を最適化するスクリプト
  • ./stuninstall.sh: StApiをアンインストールするためのスクリプト。アンインストールする際に ${STAPI_ROOT_PATH}/* と/etc/udev/rules.d/30-stcam.rulesと/etc/ld.so.conf.d/sentechSDK.confが削除されます。
