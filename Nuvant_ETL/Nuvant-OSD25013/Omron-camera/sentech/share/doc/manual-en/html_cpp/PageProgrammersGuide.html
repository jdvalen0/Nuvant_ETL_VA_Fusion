Structure of StApi

StApi supports USB3Vision, GigEVision, and CoaXPress cameras.

StApi consists of three main functionalities as follows:

  1. Camera control function (Transport Layer)
    This provides the functions to change camera settings and acquire image data and event data. The communication with cameras uses GenTL module. The GenTL module included in this SDK supports USB3Vision and GigEVision. By using the GenTL module provided by CoaXPress board makers, the StApi can also support CoaXPress cameras. To change the settings of camera, GenApi is used. If the image processing and GUI functions are not needed, the functions in the blue box can still provide basic operations with cameras.

    ModuleMain feature
    SystemFor acquiring information from CTI files(DLL files for GenTL).
    InterfaceFor setting related to interface and acquiring information from connected cameras.
    DeviceFor changing camera settings.
    Data StreamFor setting the stream related to image data.
    Stream BufferFor acquiring the information of the streaming buffer.

  2. Image processing function (Image Processing)
    This provides the functions for image processing, which consists of three types of processing/functionalities, as follows:

    TypeFeature
    Filter Process the input data and overwrite it onto original buffer. The pixel format will remain the same.
    ModuleUsage
    Field Flat Correction FilterFor correction against uneven illumination and so on.
    Noise Reduction FilterFor reducing image noise.
    Gamma Correction FilterFor Gamma correction.
    Edge Enhancement FilterFor image edge enhancement.
    Color Transformation FilterFor matrix operation on RGB data.
    Chroma Suppression FilterFor suppression coloring of high brightness/low brightness parts.
    Balance Ratio FilterFor white balance processing. This is not necessary if the camera has its own built-in white balance function.
    Graph Data FilterUsed to generate data for graph display.
    Image Averaging FilterUsed to generate averaged image data.
    Converter Convert the input data and put it into a specified output buffer.
    ModuleUsage
    Pixel Format ConverterFor pixel format conversion.
    Reverse ConverterFor vertical/horizontal inverting or rotation of images. If the camera has its own built-in reversion function, use the built-in function instead to reduce the CPU load.
    Filer Generate still image files or animated image files.
    ModuleUsage
    Still Image FilerFor saving still image into file.
    Video FilerFor saving animated image file.

  3. GUI function
    This provides the functions for displaying camera selection GUI, image preview GUI, and camera setting GUI.
    ModuleMain usage
    Device SelectionFor camera selection window
    Image DisplayFor image preview window
    Node Map DisplayFor nodemap display/setting window
    Graph DisplayFor graph display window
Structure of StApi

Environment

The StApi can be used in the following operating systems:

  • Linux: Ubuntu 18.04 (x86_64, aarch64), Raspberry Pi OS (32-bit)
  • Mac: tested on MacOS Mojave 10.14.6 and Catalina 10.15.3

If you are using a GenTL module from board makers or other producers, the supported environments may differ due to the limitation of the GenTL modules.

The StApi supports the following development environments:

  • Linux-based OS: GNU gcc (with c++11 compatibility) and Qt libraries supplied by the Linux OS distributions.

  • Mac OS: Tested on XCode 11.3, and Qt 5.8.0.

Error Handling

When an error occurs in StApi, it will generate an exception from GenICam::GenericExeption and throw it out. Following code shows how to catch and handle the error.

try
{
// Handle the exception
}
catch (const GenICam::GenericException &e)
{
std::cerr << "An exception occurred." << std::endl << e.GetDescription() << std::endl;
}

The Flow for Acquiring Image Data

  1. Include necessary header files and indicate the namespace.
    #include <StApi_TL.h>
    using namespace StApi;
    void main()
    {
  2. Initialize the StApi library.
    Call StApiInitialize() to initialize the StApi library. When the StApi library is no longer used, call StApiTerminate() to release resources. You can also call StApiInitialize() from the constructor of StApi::CStApiAutoInit as shown in the code below. This will automatically call StApiTerminate() in its destructor.
    CStApiAutoInit objStApiAutoInit;
  3. Open the System(GenTL Module) and retrieve StApi::IStSystemReleasable.
    Call CreateIStSystem() to retrieve StApi::IStSystemReleaseable. Call StApi::IStSystemReleasable::Release() after end of the use of StApi::IStSystemReleasable to release resources. You can also refer to the following code, where the destructor of StApi::CIStSystemPtr will automatically call StApi::IStSystemReleasable::Release() in its destructor.
    CIStSystemPtr pIStSystem(CreateIStSystem());
  4. Open the device(camera) and retrieve StApi::IStDeviceReleaseable.
    Call StApi::IStSystem::CreateFirstIStDevice() to retrieve the StApi::IStDeviceReleasable of the first detected device. Call StApi::IStDeviceReleasable::Release() to free the objects and resources created inside and release the retrieved StApi::IStDeviceReleasable. You can also refer to the following code that use StApi::CIStDevicePtr to manage the StApi::IStDeviceReleasable. The destructor of StApi::CIStDevicePtr will automatically call StApi::IStDeviceReleasable::Release() in its destructor.
    CIStDevicePtr pIStDevice(pIStSystem->CreateFirstIStDevice());
  5. Open the data stream to retrieve the StApi::IStDataStreamReleasable and start acquiring image data.
    Call StApi::IStDevice::CreateIStDataStream() to retrieve StApi::IStDataStreamReleasable and start acquiring image data. Call StApi::IStDataStreamReleasable::Release() to free the objects and resources created inside and release the retrieved StApi::IStDataStreamReleasable. You can also refer to the following code that use StApi::CIStDataStreamPtr to manage the StApi::IStDataStreamReleasable. The destructor of StApi::CIStDataStreamPtr will automatically call StApi::IStDataStreamReleasable::Release() in its destructor.
    CIStDataStreamPtr pIStDataStream(pIStDevice->CreateIStDataStream(0));
    pIStDataStream->StartAcquisition(100);
  6. Call StApi::IStDevice::AcquisitionStart() to start image data transmission of the camera.
    pIStDevice->AcquisitionStart();
  7. Retrieve the buffer filling with image data and queue the buffer back.
    Call StApi::IStDataStream::RetrieveBuffer() to retrieve the StApi::IStStreamBufferReleasable of buffer which filled with image data. The retrieved StApi::IStStreamBufferReleasable has to be re-queued. Call StApi::IStStreamBufferReleasable::Release() to re-queue the buffer back. You can also refer to the following code that use StApi::CIStStreamBufferPtr for buffer management. The destructor of StApi::CIStStreamBufferPtr will call StApi::IStStreamBufferReleasable::Release() in its destructor.
    while(pIStDataStream->IsGrabbing())
    {
    CIStStreamBufferPtr pIStStreamBuffer(pIStDataStream->RetrieveBuffer(5000));
    if(pIStStreamBuffer->GetIStStreamBufferInfo()->IsImagePresent())
    {
    IStImage *pIStImage = pIStStreamBuffer->GetIStImage();
    std::cout << "\r BlockId=" << pIStStreamBuffer->GetIStStreamBufferInfo()->GetFrameID()
    << " Size:" << pIStImage->GetImageWidth() << " x " << pIStImage->GetImageHeight()
    << " First byte =" << (uint32_t)*(uint8_t*)pIStImage->GetImageBuffer();
    }
    else
    {
    std::cout << "Image data is not exist" << std::endl;
    }
    }
  8. Stop the image data transmission of the camera.
    pIStDevice->AcquisitionStop();
  9. Stop acquiring image data.
    pIStDataStream->StopAcquisition();
    }

Image Acquisition

There are two methods to acquire image data. The first method is to block the main thread and waiting for image data　(refer to the sample above and sample program Grab). The second method is by using a callback function. The callback functions must be registered in advance. The registered callback functions will be called when the image data is acquired. (Refer to the sample program GrabCallback).

Callback

There are two types of callback functions in StApi. The first type is the original of StApi; the other type is the callback functions of GenApi. The callback functions originated from StApi can be registered to the module generated by StApi. For example, you can use IStDataStream interface and register callback function to DataStream module. This will let the callback function be called whenever the image data is acquired. The callback functions originated from GenApi is registered for each node of the node map (setting item) generated based on an XML file (a text file in which the setting items of a camera are described). If you register a callback function to a node related to an event, the callback function will be called when the event occurs.

Linux Installer and Uninstaller

To install the StApi SDK in Linux, uncompress the package file (*.tgz) and execute the installer file with extension .run, as follows (superuser password is required):

$ tar xf SentechSDK-xxx-xxx.tgz
$ cd SentechSDK-xxx-xxx
$ ./SentechSDK-xxx-xxx.run

By default, the installation directory is set to /opt/sentech. The installation directory is stored in environment variable STAPI_ROOT_PATH. To automatically answer all questions during installation as "Yes" and installation destination is set to /opt/sentech, use the following command:

$ ./SentechSDK-xxx-xxx.run --accept -- "-y -p /opt/sentech"
